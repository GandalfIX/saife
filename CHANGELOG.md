# Changelog

All notable changes to SAIFE Sandbox are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the version numbers
follow `docs/design/versioning.md`: SemVer adapted to a containment product, where
a change that loosens a default is never a patch. While the project is 0.x, a
minor release may break the profile schema; the error message names the fix.

## [Unreleased]

### Changed

- **The test suite no longer listens on a non-loopback address.** The forward-path fixtures served
  their stand-in origin on the host's LAN address, and Windows Firewall asks once per executable
  *file* - so every rebuild (and every `cargo-mutants` copy of the tree) produced a new prompt, and
  answering it left an inbound rule per binary. The fixtures now serve the origin on `127.0.0.1`;
  the loopback legs are open only for a listener built by the `cfg(test)`-only `spawn_loopback`, so
  the product rule that refuses loopback targets is unchanged and still pinned by
  `loopback_refused_even_when_allowlisted`. `maintenance/` is new: it holds
  `Remove-StaleSaifeFirewallRules.ps1` (cleans up the rules a host already accumulated) and the
  two AppContainer-ACE recovery scripts that used to sit in `tests/` - they are host repairs, not
  tests, and nothing in the suite calls them.

## [0.6.0] - 2026-11-12

The release that turns the credential deny list from one hard-coded opinion into a **classified
floor with two deliberate ways to adjust it**: a machine-wide policy an administrator deploys, and
a per-session exposure an operator names. It also makes every distribution carry its third-party
licenses and SBOMs, and puts the two containment backends behind one trait so the teardown they
share can be tested once.

### Added

- **Machine policy for credential denies (additive).** `%PROGRAMDATA%\saife\deny.d\*.json` adds
  deny entries for every session on the machine, on both backends. Additive by construction: the
  schema has no `allow` key, so a policy can hide more but never un-hide what the code denies, and
  `deny_unknown_fields` refuses a moved key instead of aliasing it. Files load in sorted order;
  an unparseable file, an unknown key, a version this build does not speak, a file that adds
  nothing, or a relative/`..` path refuses the session by name (a policy that cannot be trusted to
  parse cannot be trusted to deny). `$CWD`/`$SID` are refused: a policy names a real path. The
  policy directory itself is denied to the workload - the file names alone say where the org keeps
  secrets.
- **`saife credentials`** prints the effective deny set: every builtin entry with its class, the
  path it covers, and the machine policy's additions with the files they came from. It is the only
  place an operator can see what a session will deny *before* launching it.
- **Credential classes and `--expose-credential <label>`.** The always-denied set is classified:
  `secret` (`.ssh`, `.aws`, `.azure`, `.gnupg`, `~/.config/gcloud`, the tool's own control plane)
  and `tool-credential` (gradle, maven, cargo, git, docker, kube, gh, pypi, nuget). The flag drops
  exactly one `tool-credential` entry for one session, prints the label and path on stderr, and
  records it in the session's root audit leaf (`exposed_credentials`: label, path, class - never
  the value). A `secret` label and an unknown label are refused before a single ACE is written; the
  default stays deny. This is the deliberate-use path for a tool that cannot run otherwise -
  serving the credential without exposing it is F-2 (ADR-0001, selective TLS termination at the
  proxy), which is not in this release.
- **Google Cloud's credential store is denied with the builtin set.** `~/.config/gcloud` and the
  Windows spelling `%APPDATA%\gcloud` hold `credentials.db` and `access_tokens.db` - live OAuth
  tokens. Both are class `secret` and never exposable, matching `.aws` and `.azure`.
- **Third-party licenses and SBOM in every distribution.** `dist/` and every archive carry
  `THIRD-PARTY-LICENSES.md` (the full license text of every dependency compiled into the binaries,
  generated by `cargo about` from `Cargo.lock`) and two CycloneDX 1.6 SBOMs
  (`saife-<version>-sbom-x64/arm64.cdx.json`, generated by `cargo cyclonedx`). The MIT, Apache-2.0,
  BSD, ISC, Unlicense and Unicode-3.0 licenses require the text to be reproduced in every
  distribution of the binary; the EU Cyber Resilience Act requires a machine-readable SBOM. The
  artifacts are generated by `packaging/licenses/generate.ps1` during `build-dist.ps1` and never
  hand-edited: an accepted-license list (`packaging/licenses/about.toml`) fails the build when a
  dependency carries a license outside it, and `release.ps1` refuses an asset that does not
  contain the files (the guard is exercised by `packaging/tests/licenses-guard.ps1`).
- **One-command developer setup.** `pwsh -File start-develop.ps1 -Install` runs
  `packaging/check-prereqs.ps1` and the new `packaging/check-devtools.ps1` (cargo-deny,
  cargo-mutants, cargo-shear, with optional geiger/fuzz/Miri), never elevated, and offers to
  install what is missing. Tools resolve by path rather than by a possibly stale shell `PATH`.

### Changed

- `builtin_deny_dirs()`/`builtin_deny_files()` were replaced by one classified set
  (`credential_denies()`), which both backends consume through `effective_denies()`. The flat
  lists could disagree with each other (they did: the mxc list named four trees, the AppContainer
  list six); one source of truth is what makes "the same deny on both backends" checkable.
- The session root leaf records the machine policy in force (`credential_policy`: dirs, files,
  source file names) when one is deployed, and the exposures when there are any. Both keys are
  omitted otherwise, so "none" stays distinguishable from "not recorded".
- **The two backends sit behind one `ContainmentBackend` trait.** The session flow no longer
  branches into two copies of teardown; the OS primitives are reached through one interface, which
  is what let the teardown be pinned by scenario for the first time (below).
- Teardown postconditions are now scenarios: S-96 asserts the AppContainer profile footprint
  exists during a held session and is gone after it, S-97 the session install tree, S-98 the DACL
  journal file. Each one observes the artifact during the session, so "gone after" cannot pass
  vacuously; mutation-tested by disabling the three mechanisms.
- A DACL journal whose owning process is gone is no longer treated as this run's to restore - a
  recycled PID or a dead child cannot block a journal from being retired.

### Behaviour changes

- `~/.config/gcloud` and `%APPDATA%\gcloud` are denied. A session that could read GCP's
  `credentials.db` or `access_tokens.db` before cannot any more. There is no exposure for them:
  they are class `secret`.
- `~/.config/gh` is now denied as a **tree**. Before 0.6.0 the entry was written as a file deny,
  so the ACE did not inherit and `hosts.yml` inside the directory stayed readable through a grant
  on `~/.config`. A session that read that file (through such a grant) will now be refused at
  start unless it names `--expose-credential gh`.
- A host without `~/.aws`, `~/.azure` or `~/.gnupg` no longer fails its deny ACEs: the missing
  trees are skipped instead of failing the grant pass.

### Notes

- `~/.npmrc` is deliberately **not** denied: npm must read it to find both the registry URL and
  its auth token, so denying it breaks every authenticated install. The token in it stays a
  documented residual.
- Serving a credential without ever making it readable - the proxy injects the header, the file
  never enters the sandbox - is F-2 in ADR-0001 and needs selective TLS termination. Not shipped.

## [0.5.0] - 2026-11-09

The release that adds the **ssh-gateway plugin** and the **declared-loopback session mode**, and
that lands the independent security review of 2026-11-09: 39 findings re-tested against the code,
29 confirmed, 12 partial, 1 wrong (a junction inside the project fails the pack instead of
exfiltrating it). Containment is unchanged or **stricter** throughout; the two behaviour changes
that can refuse something that used to "work" are named under Changed.

### Added

- **ssh-gateway plugin.** A sandboxed workload names a verb on a declared host; the sidecar runs the
  real `ssh` on the host with keys that never enter the container, and the workload receives the
  bytes. This is the designed way out for a tool that sshs to a server - the identity file sits
  behind the `.ssh` deny grant and port 22 is kernel-denied by design - without weakening either.
  Hosts and per-host verb allowlists come from a gateway file; every call is audited twice: one
  `op=FACADE` leaf with the sidecar's own HTTP status, and one structured EXEC line on the sidecar
  log (host, verb, argument digest, sizes, exit, duration).
- **`--allow-host-loopback`** (ADR-0007). The mxc substrate closes loopback as a property of proxy
  mode, not of egress policy, so a per-port allowance - the mechanism the ADR first proposed - does
  not exist. What ships is the honest remainder: a session mode with loopback **open, unscoped and
  unaudited**, internet egress still passing the audited decision pipeline, and the risk printed as
  a pinned startup warning. The session-start leaf records `loopback: open-unscoped`. Gradle builds
  still belong on `--runner`.
- **LAN egress denied by default.** A wildcard allow-list entry resolving into `10/8`,
  `172.16/12`, `192.168/16`, `100.64/10` or `fc00::/7` used to dial the local network and audit as
  allowed; those ranges are now refused on the direct path (`lan_refused`). `--allow-lan` relaxes
  the LAN leg only - loopback and link-local stay refused.
- **Built-in credential-file denies.** The shipped profiles grant `~/.gradle` and `~/.m2` RWX, and
  those trees hold `gradle.properties` and `settings.xml`. Where a whole-directory deny cannot work
  (the pre-flight refuses a grant inside a deny), the files are denied individually:
  `gradle.properties`, `.m2/settings.xml`, `.cargo/credentials.toml`, `.git-credentials`,
  `.docker/config.json`, `.kube/config`, `.config/gh`, `%APPDATA%\NuGet\NuGet.Config`, `.pypirc`.
  (`.npmrc` stays readable on purpose - npm needs the token; the trade-off is in `profiles/README.md`.)
- **`req_id` on request leaves and as an audit filter key.** The admission allow and any post-dial
  deny of the same request share an id, so `--filter req_id=17` selects exactly that request's
  allow+deny, and `audit show` counts a host as contacted only when the terminal disposition is allow.

### Security

- **Deny ACEs carried a zero access mask since the MVP.** A `DENY_ACCESS` ACE with mask 0 intersects
  no requested right, so the six builtin-deny trees and every profile deny denied **nothing**: a
  session granted `--allow $USERPROFILE` could read `~/.ssh`, `~/.aws`, `~/.azure`, `~/.gnupg` and
  both `.saife` trees through the inherited allow. The mask is now `FILE_ALL_ACCESS` with
  propagation, and `path_covers` normalizes like the admission path so a grant spelled into a deny
  cannot slip past the pre-flight.
- **Runner sync-out refused junctions and link entries.** The workload owns the writable project,
  so it could pre-create `build/libs` as a junction and have the supervisor write through it with
  the user's rights; the tar crate's containment check canonicalizes and follows such a junction.
  Entry kinds are pre-scanned, every existing component is checked for reparse points, and the
  destination must resolve under the canonical project - in `sync_out` itself, because the junction
  can be planted while the build runs.
- **The audit chain has one writer per session id**, a lock carrying the holder's pid and creation
  stamp (a crashed run is reaped, a recycled pid is not honoured). `.sig` is published before
  `.root`, each through a sibling temp and `MoveFileExW(REPLACE|WRITE_THROUGH)`, so a kill in
  between reads as INCOMPLETE instead of TAMPERED. Appends after seal are counted and printed
  instead of vanishing, and a failed non-strict write no longer advances the chain - a degraded log
  used to verify as TAMPERED because the next leaf named a parent that was never written.
- **`audit verify` no longer mints a signing key.** It called `ensure()` and installed a fresh trust
  anchor when the key was missing, turning key loss into BAD_SIGNATURE for every old session;
  it reports `KEY_MISSING` and creates nothing. A key fingerprint (`.keyfp`) distinguishes a
  rotation from a substitution (`KEY_CHANGED`), with the honest caveat that a per-session
  fingerprint cannot tell them apart without a trust store.
- **Readers refuse what the writer refuses.** Session ids are validated at both reader entry points
  (a traversal, absolute or UNC id used to read or write outside the session directory), a
  non-ASCII `.sig` is BAD_SIGNATURE instead of a panic, a leaf without `sid` or `seq` is Tampered,
  and `audit show` prints "PRESENT (not verified)" instead of claiming "Sig OK" from file existence.
- **Teardown strips the session's deny ACEs too.** `REVOKE_ACCESS` removes allow ACEs and leaves
  deny ones behind, so the six builtin-deny trees kept a permanent `FILE_ALL_ACCESS` deny for a
  deleted AppContainer SID. Restore rebuilds each journaled DACL without every ACE for the session
  SID (allow, deny, explicit, inherited), merges the journaled prior ACEs back, and applies it -
  copying raw ACEs so other trustees and inherited flags stay byte-identical. Each path is restored
  once; a later journal entry can no longer resurrect dead ACEs.
- **ssh-gateway hardening.** A plugin-local `known_hosts` with `StrictHostKeyChecking=yes` (first
  contact used to be silent TOFU into the user's real `~/.ssh/known_hosts`); framed body reads
  (negative or non-numeric `Content-Length`, `Transfer-Encoding` refused); `ssh.exe` resolved once
  by absolute path instead of through a `PATH` that starts with the plugin directory; the child
  environment cleared and rebuilt from an allowlist, so `AWS_*`, `GITHUB_TOKEN` and proxy variables
  no longer reach a sidecar.
- **Runner hardening.** Build logs are a ring with a line cap and a 4 MiB budget (a build printing
  gigabytes used to fill the supervisor's heap, bounded only by the deadline); the container gets
  `PidsLimit 1024`, 4 CPUs and >= 4 GiB memory (overridable via `SAIFE_RUNNER_*`); the runner token
  compares in constant time; head and body reads have deadlines (408 on timeout); control
  characters are refused in `project` and `paths`; `.sandbox/<sid>` is removed at teardown; and a
  junction or file symlink inside the project is refused by name instead of producing an opaque
  pack failure.
- **Network honesty.** A chained dial deliberately resolves nothing locally, which voids the
  destination hard-deny when the upstream is the loopback bridge this module recommends - dial
  behaviour is unchanged (a local pre-check would false-deny under split-horizon DNS), but a
  loopback upstream now prints a named warning and ADR-0001 states the guarantee's real scope.
  `CONNECT user@host:443` no longer carries userinfo into the decision, `Proxy-Authenticate` /
  `Proxy-Info` are stripped from every relayed head, body reads have a deadline (128 idle
  authenticated connections used to park every permit), and the facade relays the declared path
  while the audit leaf keeps the origin-form.
- **`--allow <path>:write` and `:execute` are refused** with an error naming the supported modes
  (`read`, `readwrite`). Both were parsed and then discarded: every mode except `read` became a
  full RWX grant, while the user guide promised "write only". `:read` now yields RX, `:readwrite`
  and a bare `--allow` yield RWX.
- **The credential-deny base comes from `SHGetKnownFolderPath`**, not from a caller-controlled
  `USERPROFILE`: unset, all six directory and nine file denies silently vanished; repointed, they
  denied the wrong tree. `.sandbox` carries a PROTECTED DACL (a second session could enumerate
  sibling SIDs, create entries and rename another session's tree), and a journal that cannot be
  read fails closed instead of parsing as empty - which deleted the journal and left every granted
  ACE on the host forever.
- **Runner token refusals drain the declared body** before answering: closing a socket with unread
  inbound data makes Windows send a RST, and the tail of the 401 was destroyed before the client
  read it - a truncated header that looked like a protocol error.
- **The shipped ssh-gateway manifest parses.** `"max_concurrent": 4` was a JSON number in a
  `BTreeMap<String, String>`, so the plugin could never load (stop-ship, found by the verdict pass
  and not by any test). Every shipped `plugin.json` is now parsed by the real loader in a test.

### Changed

- `audit show` counts a host as contacted only for a request whose **terminal** disposition is
  allow; the admission allow used to be counted even when the dial was then denied.
- `install-local.ps1`'s self-check captures `saife setup --check-only` before printing instead of
  piping into `Select-Object -First 4`, which closed the child's stdout mid-output and made a clean
  install end in a Rust panic (`os error 232`).
- `release.ps1` treats an already-deleted release branch as the expected case instead of exiting
  non-zero after a successful publish.
- The opencode profile grants `$HOME/.local/bin` and `$APPDATA/uv` read access, so a bare `opencode`
  resolves and a uv-managed python can spawn its interpreter - both used to report as
  `0x80070002` or `permission denied (os error 5)`.

### Docs

- ADR-0007 (declared loopback reach): Accepted, with the spike measurements, the shipped
  implementation and the standing rule that Gradle builds prefer the runner (ADR-0006).
- `docs/design/2026-11-09-security-review-verdicts.md`: the independent verdicts, per point, with
  severity moves and the red test that flips each fix.
- FAQ: opencode v2 under mxc needs loopback; `0x80070002` from a missing PATH-directory grant, with
  the uv-trampoline variant.
- `plugins/ssh-gateway/README.md`: install, gateway-file format, the eight invariants, seeding the
  plugin-local `known_hosts` with `ssh-keyscan`.

### Notes

- No profile schema change: a 0.4.x profile loads unchanged. The new refusals are defaults that were
  previously *silent* (zero-mask denies, LAN dials) or dishonest (grant modes); the escape hatches
  are `--allow-lan` and, for loopback, `--allow-host-loopback`.
- The built-in credential-file denies are not configurable per profile. A workflow that must read one
  of those files inside a session is out of scope by design - put the values in the build facade or
  copy them into the project.
- `--allow-host-loopback` opens **every** host loopback service to the session and audits none of
  that traffic. It is a product decision recorded in ADR-0007, not a scoping mechanism; the
  per-port allowance the ADR originally wanted does not exist in the substrate.

## [0.4.0] - 2026-11-04

The release that adds the **build runner**, and the first one that ships an **arm64** archive.
Containment is unchanged or stricter; the one behaviour that loosens is that `--runner` may now be
used with `--block-net`, which previously refused to start at all.

### Added

- **Build runner.** Toolchains whose daemons need loopback - Gradle, a TCP test harness - cannot run
  inside a session, and loopback is closed in both directions. `saife run --runner` publishes a
  facade the session reaches at `build.sandbox.invalid`; the build runs in a digest-pinned container
  the supervisor owns, with no network, reached only through declared `(POST|GET /build)`
  operations. Slots are owned by pid **and** creation time, capped, and reaped when idle.
- `saife runner prewarm` fills a shared cache volume with every resolvable Maven-style configuration
  (compile, runtime, test-compile, test-runtime), so an offline build has what it needs; `saife
  runner status` reports slots and cache size.
- **Allow-list for what is copied into the container**: `paths` on the build request, defaulted by
  `runner.sync.paths` in a profile. A closed set - the settings closure travels or the build fails -
  and a missing entry is refused by name.
- **arm64 archives**: `saife-<version>-arm64.zip` next to the x64 one, with architecture-aware
  `build-dist.ps1`, `release.ps1`, `install-local.ps1` and `install.ps1` (an ARM64 host prefers the
  native archive and falls back to x64 with an emulation warning; an x64 host never gets arm64).
  The winget manifest carries one `Installer` block per architecture.
- `packaging/check-prereqs.ps1`: reports each build prerequisite, prints the exact install command
  for anything missing, offers to run it, and never elevates. It compares the Windows *servicing*
  level and reads the PE machine of built binaries rather than trusting a file name.
- Two opencode skills: `saife-build` (trigger the runner from inside a session) and `saife-maven`
  (Maven builds in-process, so it needs the proxy and a writable repository, not the runner).

### Changed

- A session can serve its facades **with no egress at all**: the proxy gains a blocked posture that
  denies every request at the tier check while still routing facade hosts. `--runner --block-net` is
  therefore the recommended pairing - previously it refused to start.
- `saife setup` names a tier it would have to **refuse**, instead of printing a degraded tier as if
  it were a green light.
- `learned list` shows every profile's store and says which one a revoke missed; profile grants are
  de-duplicated after expansion and share one resolver.
- `install-local.ps1` refuses a stale build of the same version; `install.ps1` diagnoses an
  application-control block (Smart App Control, AppLocker, WDAC) instead of dumping a stack trace.

### Fixed

- Gradle builds no longer fail on a missing executable bit, or on a container copy that races the
  slot's own `mkdir` (`404 /src`).
- `pack_dir` applies its skip list at every level, so a composite build no longer ships its own
  `build/` directories into the container.
- `prewarm` resolves every configuration, not just `runtimeClasspath`, so a new `testImplementation`
  is picked up by re-running it.

### Notes

- Profile schema: `runner.sync.paths` is new and additive. No key was removed or renamed, so a 0.3.x
  profile loads unchanged.
- The runner is **not** enabled by default and never runs a build with network.
- The arm64 archive is cross-built and has **not been run on ARM hardware**; the README says so, and
  an ARM64 host can install the x64 archive under emulation instead.


## [0.3.1] - 2026-10-26

Documentation, distribution and output only: no profile, no default and no exit
code changes, so a setup that worked under 0.3.0 works unchanged.

### Added

- `install.ps1`: one-command install (download, hash-verify against the release's
  `SHA256SUMS.txt`, extract, version-check, user-PATH entry, self-check). It is the
  supported install channel and needs no administrator rights.
- `saife setup --check-only` prints an `MXC tier (probe)` line: it probes a
  representative base request and reports the verdict, so a machine whose probe
  names no tier is visible before a run refuses.

### Changed

- `packaging/release.ps1` no longer pushes `main`. Releasing is two steps: prepare
  (build, probe, rewrite manifests, open a pull request) and `-Publish` (on `main`
  after the merge: tag, publish, verify). `main` only moves through pull requests now
  - see `AGENTS.md`.
- No winget package is provided. `packaging/winget/` remains for local
  `winget install --manifest` use; `install.ps1` is the supported install.
- The guardrail-2 refusal for a host whose MXC tier probe names no tier now ends
  with the way out - use `--backend appcontainer`, or run `saife setup
  --check-only` - instead of a dead end.
- The winget manifests moved to the 1.12 schema, and the manifest rewrite keeps the
  file's CRLF endings.

### Docs

- FAQ entry for the writable-grant-covers-launcher refusal: why `--allow-cwd` in the
  home directory is refused for the mxc backend, with the measured contract (message,
  exit code 2, no audit session) and the workaround.

## [0.3.0] - 2026-10-26

First public release. Early stages: the tool works end to end, but the profile
schema and the CLI still move, and a 0.x minor release can break a profile that
worked before.

- Windows 11 24H2 (build 26100) or newer, x64. No administrator rights, no service
  and no installer are needed for the default `mxc` backend.
- Start with `README.md` for install and a first run, then `docs/USER-GUIDE.md` for
  every flag, the guardrail proof line and the audit log.
- The binaries are unsigned, so Windows SmartScreen warns about an unknown
  publisher on first run. Check the download against `SHA256SUMS.txt` on the
  release page.
