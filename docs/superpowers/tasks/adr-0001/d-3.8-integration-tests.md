The new scenarios (S-72..S-80) build on those, testing the D-1 pipeline and D-3/D-4 features.

### S-72: deny_domain precedence (automated)

**What:** `--allow-domain` permits a host, but `--deny-domain` blocks it. The deny wins ([G-32, G-33]).

```powershell
# S-72: deny_domain precedence — deny wins over allow.
function Invoke-Scenario-S72 {
    $d = New-ScenarioDir 72
    $r = Invoke-Sandbox -Args @(
        'run','--allow-cwd',
        '--allow-domain','*.evil.com',
        '--deny-domain','*.evil.com',
        '--no-prompt',
        '--','cmd','/c','curl','-s','-o','NUL','-w','%{http_code}',
        'https://evil.example.com'
    ) -WorkingDirectory $d
    $out = ($r.Stdout -join '')
    $passed = ($out -match '403')
    return @{ Num=72; Name='S-72 (deny_domain precedence)'; Passed=$passed; Skipped=$false
        Detail = if ($passed) { 'deny_domain blocked despite allow-domain' } else { "exit=$($r.ExitCode) stdout=$out" } }
}
```

**Setup:** Temp dir, `--allow-domain *.evil.com --deny-domain *.evil.com --no-prompt`.
**Command:** `curl https://evil.example.com` inside the sandbox.
**Expected:** HTTP 403 (deny wins). The audit log shows `source: "blocklist"`.

### S-75: loopback CONNECT refused (automated)

**What:** The proxy refuses CONNECT to loopback hosts with `403` + `X-Sandbox: denied` ([G-44]).

```powershell
# S-75: loopback CONNECT refused — 403 + X-Sandbox: denied.
function Invoke-Scenario-S75 {
    $d = New-ScenarioDir 75
    # Start a dummy local server on a high port, then try CONNECT to it
    # through the proxy.
    $listener = [System.Net.Sockets.TcpListener]::new([System.Net.IPAddress]::Loopback, 0)
    $listener.Start()
    $localPort = $listener.LocalEndpoint.Port
    $listener.Stop()

    # Run the sandbox with a proxy, then from inside issue a CONNECT to
    # 127.0.0.1:<localPort> via curl -x.
    $r = Invoke-Sandbox -Args @(
        'run','--allow-cwd',
        '--allow-domain','127.0.0.1',
        '--no-prompt',
        '--','cmd','/c','curl','-s','-o','NUL','-w','%{http_code}',
        '-x',"http://sandbox:dummy@127.0.0.1:%SANDBOX_PROXY_PORT%",
        'https://127.0.0.1'
    ) -WorkingDirectory $d -Diag
    $out = ($r.Stdout -join '')
    $passed = ($out -match '403')
    return @{ Num=75; Name='S-75 (loopback CONNECT refused)'; Passed=$passed; Skipped=$false
        Detail = if ($passed) { 'loopback CONNECT refused with 403' } else { "exit=$($r.ExitCode) stdout=$out" } }
}
```

**Setup:** A sandbox session with a proxy; `--allow-domain 127.0.0.1 --no-prompt`.
**Command:** `curl -x http://sandbox:<token>@127.0.0.1:$SANDBOX_PROXY_PORT https://127.0.0.1` (forces a CONNECT to loopback).
**Expected:** HTTP 403 + `X-Sandbox: denied` header. Audit `source: "hard-deny"`.

**Note:** The exact mechanism for getting `$SANDBOX_PROXY_PORT` inside the sandbox depends on D-0.3's env var injection. The test may need to read it from `SANDBOX_DIAG` stderr or from the env block. Adjust the test to extract the port from the sandbox's stderr or env.

### S-77: intent endpoint POST + GET (automated)

**What:** The intent registry endpoints accept POST + GET on the proxy listener ([G-7, G-38, G-57]).

```powershell
# S-77: intent endpoint POST + GET.
function Invoke-Scenario-S77 {
    $d = New-ScenarioDir 77
    # Run a script inside the sandbox that POSTs an intent, then GETs it.
    $script = @'
@echo off
set PORT=%SANDBOX_PROXY_PORT%
set TOKEN=%SANDBOX_PROXY_TOKEN%
curl -s -o NUL -w "POST=%%{http_code}" -H "Proxy-Authorization: Basic %TOKEN%" http://127.0.0.1:%PORT%/sandbox/intent -d "{\"target\":\"api.example.com\",\"reason\":\"test\"}"
echo.
curl -s -H "Proxy-Authorization: Basic %TOKEN%" "http://127.0.0.1:%PORT%/sandbox/intent?host=api.example.com"
'@
    $scriptPath = Join-Path $d 'test-intent.bat'
    Set-Content -LiteralPath $scriptPath -Value $script
    $r = Invoke-Sandbox -Args @(
        'run','--allow-cwd','--allow-domain','api.example.com','--no-prompt',
        '--','cmd','/c',$scriptPath
    ) -WorkingDirectory $d -Diag
    $out = ($r.Stdout -join "`n")
    $passed = ($out -match 'POST=204') -and ($out -match 'api.example.com')
    return @{ Num=77; Name='S-77 (intent POST+GET)'; Passed=$passed; Skipped=$false
        Detail = if ($passed) { 'intent POST 204 + GET 200' } else { "exit=$($r.ExitCode) stdout=$out" } }
}
```

**Setup:** A sandbox session with the proxy. The inner script uses `SANDBOX_PROXY_PORT` + `SANDBOX_PROXY_TOKEN` env vars (from D-0.3) to reach the intent endpoints.
**Command:** POST `/sandbox/intent` with `{"target":"api.example.com","reason":"test"}`, then GET `/sandbox/intent?host=api.example.com`.
**Expected:** POST → `204 No Content`. GET → `200 OK` with JSON containing the reason.

**Note:** The `SANDBOX_PROXY_TOKEN` env var must contain the `Basic` credentials (or the test constructs the `Basic <base64>` header). Adjust based on the env var contract from D-0.3.

### S-78: learned persistence across restart (MANUAL)

**What:** An interactive "Allow permanently" decision persists to the learned file; after restarting the sandbox, the host is allowed without a dialog ([G-5, G-56]).

```powershell
# S-78: learned persistence across restart (MANUAL — requires dialog click).
function Invoke-Scenario-S78 {
    $d = New-ScenarioDir 78
    # Pre-populate the learned file to make this automatable without a click.
    # In the manual version, the user clicks "Allow permanently" in the dialog.
    $learnedDir = Join-Path $env:USERPROFILE '.sandbox\learned'
    if (-not (Test-Path -LiteralPath $learnedDir)) { New-Item -ItemType Directory -Path $learnedDir -Force | Out-Null }
    $learnedFile = Join-Path $learnedDir 'default.json'
    $learnedJson = '{"schema":1,"allow":[{"host":"github.com","scope":"host"}],"deny":[]}'
    Set-Content -LiteralPath $learnedFile -Value $learnedJson

    $r = Invoke-Sandbox -Args @(
        'run','--allow-cwd',
        '--allow-domain','api.anthropic.com',
        '--no-prompt',
        '--','cmd','/c','curl','-s','-o','NUL','-w','%{http_code}',
        'https://github.com'
    ) -WorkingDirectory $d
    $out = ($r.Stdout -join '')
    # GitHub returns 200/301/302 for the root — connection allowed.
    $passed = ($out -match '200') -or ($out -match '301') -or ($out -match '302')
    # Clean up the learned file.
    Remove-Item -LiteralPath $learnedFile -Force -ErrorAction SilentlyContinue
    return @{ Num=78; Name='S-78 (learned persistence)'; Passed=$passed; Skipped=$false
        Detail = if ($passed) { 'learned allow persisted across restart' } else { "exit=$($r.ExitCode) stdout=$out" } }
}
```

**Setup:** Pre-populate `%USERPROFILE%\.sandbox\learned\default.json` with an allow entry for `github.com`. Run the sandbox with `--allow-domain api.anthropic.com` (NOT github.com) + `--no-prompt`.
**Command:** `curl https://github.com`.
**Expected:** Connection succeeds (learned allow from the file applies even though github.com is not in `--allow-domain`).

**Manual variant:** Remove the pre-population; instead run without `--no-prompt`, click "Allow permanently (this host)" in the dialog, then restart the sandbox and curl again — verify it succeeds without a dialog. The manual test is in Checkpoint 3.

### S-79: `sandbox learned list/revoke` (automated, if S-78 done)

**What:** The `sandbox learned` CLI subcommand lists and revokes decisions ([G-51]).

```powershell
# S-79: sandbox learned list/revoke.
function Invoke-Scenario-S79 {
    $d = New-ScenarioDir 79
    # Pre-populate a learned entry.
    $learnedDir = Join-Path $env:USERPROFILE '.sandbox\learned'
    if (-not (Test-Path -LiteralPath $learnedDir)) { New-Item -ItemType Directory -Path $learnedDir -Force | Out-Null }
    $learnedFile = Join-Path $learnedDir 'default.json'
    $learnedJson = '{"schema":1,"allow":[{"host":"api.example.com","scope":"host"}],"deny":[]}'
    Set-Content -LiteralPath $learnedFile -Value $learnedJson

    # `sandbox learned list` should show the entry.
    $r1 = Invoke-Sandbox -Args @('learned','list')
    $out1 = ($r1.Stdout -join "`n")
    $listOk = ($out1 -match 'api.example.com') -and ($out1 -match 'allow')

    # `sandbox learned revoke api.example.com` should remove it.
    $r2 = Invoke-Sandbox -Args @('learned','revoke','api.example.com')
    $out2 = ($r2.Stdout -join "`n")
    $revokeOk = ($out2 -match 'Revoked')

    # `sandbox learned list` should now be empty.
    $r3 = Invoke-Sandbox -Args @('learned','list')
    $out3 = ($r3.Stdout -join "`n")
    $emptyOk = ($out3 -match 'no learned decisions')

    $passed = $listOk -and $revokeOk -and $emptyOk
    Remove-Item -LiteralPath $learnedFile -Force -ErrorAction SilentlyContinue
    return @{ Num=79; Name='S-79 (sandbox learned list/revoke)'; Passed=$passed; Skipped=$false
        Detail = if ($passed) { 'list → revoke → list-empty' } else { "list=$listOk revoke=$revokeOk empty=$emptyOk" } }
}
```

**Setup:** Pre-populate the learned file with an entry. Run `sandbox learned list`, `sandbox learned revoke <host>`, `sandbox learned list`.
**Expected:** First list shows the entry; revoke succeeds; second list is empty.

### S-80: audit source filter (automated)

**What:** The audit filter `source=<value>` filters CONNECT events by their `source` field (from D-5.1 / D-5.4).

```powershell
# S-80: audit source filter — source=hard-deny shows only hard-deny events.
function Invoke-Scenario-S80 {
    $d = New-ScenarioDir 80
    # Run a session that produces both a hard-deny and an allow event.
    $psid = Invoke-Sandbox -Args @(
        'run','--allow-cwd','--print-sid',
        '--allow-domain','api.anthropic.com',
        '--no-prompt',
        '--','cmd','/c','curl','-s','-o','NUL','https://169.254.169.254','&&','curl','-s','-o','NUL','-w','%{http_code}','https://api.anthropic.com'
    ) -WorkingDirectory $d
    if ($psid.ExitCode -ne 0) { return @{ Num=80; Name='S-80 (audit source filter)'; Passed=$false; Skipped=$false; Detail="print-sid failed" } }
    $sid = ($psid.Stdout | Select-String -Pattern '^[A-F0-9]{16,}' | Select-Object -First 1).ToString().Trim()

    # Filter for source=hard-deny.
    $r = Invoke-Sandbox -Args @('audit','show',$sid,'--filter','source=hard-deny','--json')
    $json = ($r.Stdout -join "`n")
    $hasHardDeny = $json -match '"source"\s*:\s*"hard-deny"'
    $noAllowlist = $json -notmatch '"source"\s*:\s*"allowlist"'

    $passed = $hasHardDeny -and $noAllowlist
    return @{ Num=80; Name='S-80 (audit source filter)'; Passed=$passed; Skipped=$false
        Detail = if ($passed) { 'source=hard-deny filter works' } else { "hasHardDeny=$hasHardDeny noAllowlist=$noAllowlist" } }
}
```

**Setup:** A sandbox session that produces both a hard-deny event (curl `169.254.169.254`) and an allow event (curl `api.anthropic.com`).
**Command:** `sandbox audit show <sid> --filter "source=hard-deny" --json`.
**Expected:** Only hard-deny events in the output; no allowlist events.
