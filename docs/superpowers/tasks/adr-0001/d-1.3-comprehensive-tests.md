### S-84: pipeline ordering — deny_domain over allow (automated)

**What:** A host in both `deny_domain` and `allow_domain` is denied with `source: "blocklist"` (deny wins). [G-32, G-33] This is the end-to-end version of D-1.1 Test A.

```powershell
# S-84: pipeline ordering — deny_domain precedence over allow_domain.
function Invoke-Scenario-S84 {
    $d = New-ScenarioDir 84
    $r = Invoke-Sandbox -Args @(
        'run','--allow-cwd',
        '--allow-domain','*.evil.com',
        '--deny-domain','*.evil.com',
        '--no-prompt',
        '--','cmd','/c','curl','-s','-o','NUL','-w','%{http_code}',
        'https://evil.example.com'
    ) -WorkingDirectory $d
    $out = ($r.Stdout -join '')
    $passed = ($out -match '403')
    return @{ Num=84; Name='S-84 (deny_domain over allow)'; Passed=$passed; Skipped=$false
        Detail = if ($passed) { 'deny_domain blocked despite allow-domain (403)' } else { "exit=$($r.ExitCode) stdout=$out" } }
}
```

**Setup:** `--allow-domain *.evil.com --deny-domain *.evil.com --no-prompt`.
**Command:** `curl https://evil.example.com`.
**Expected:** HTTP 403 (deny wins). Audit `source: "blocklist"`.

### S-85: pipeline ordering — learned-deny over deny_domain (automated)

**What:** A host that is both learned-denied AND in `deny_domain` is denied with `source: "learned"` (the user's explicit past decision is more informative). [G-33] This is the end-to-end version of D-1.1 Test B. The learned file is pre-populated before the run.

```powershell
# S-85: pipeline ordering — learned-deny precedence over deny_domain.
function Invoke-Scenario-S85 {
    $d = New-ScenarioDir 85

    # Pre-populate the learned file with a DENY for evil.example.com.
    $learnedDir = Join-Path $env:USERPROFILE '.sandbox\learned'
    if (-not (Test-Path -LiteralPath $learnedDir)) { New-Item -ItemType Directory -Path $learnedDir -Force | Out-Null }
    $learnedFile = Join-Path $learnedDir 'default.json'
    $learnedJson = '{"schema":1,"allow":[],"deny":[{"host":"evil.example.com","scope":"host"}]}'
    Set-Content -LiteralPath $learnedFile -Value $learnedJson

    # Run with both deny_domain and allow_domain containing the host.
    # The learned-deny should take precedence in the audit source.
    $r = Invoke-Sandbox -Args @(
        'run','--allow-cwd',
        '--allow-domain','*.evil.com',
        '--deny-domain','*.evil.com',
        '--no-prompt',
        '--','cmd','/c','curl','-s','-o','NUL','-w','%{http_code}',
        'https://evil.example.com'
    ) -WorkingDirectory $d
    $out = ($r.Stdout -join '')

    # Get the session ID from the audit to verify the source field.
    # (The sandbox prints the SID on the audit log; we can also use --print-sid.)
    $passed = ($out -match '403')

    # Clean up the learned file.
    Remove-Item -LiteralPath $learnedFile -Force -ErrorAction SilentlyContinue

    return @{ Num=85; Name='S-85 (learned-deny over deny_domain)'; Passed=$passed; Skipped=$false
        Detail = if ($passed) { 'learned-deny precedence: denied (403)' } else { "exit=$($r.ExitCode) stdout=$out" } }
}
```

**Setup:** Pre-populate `%USERPROFILE%\.sandbox\learned\default.json` with a deny entry for `evil.example.com`. Run with `--allow-domain *.evil.com --deny-domain *.evil.com --no-prompt`.
**Command:** `curl https://evil.example.com`.
**Expected:** HTTP 403 (denied). Audit `source: "learned"` (NOT `source: "blocklist"` — the learned-deny takes precedence).
**Note:** the automated test verifies the 403 response. To verify the `source: "learned"` attribution, inspect the audit log with `sandbox audit show <sid> --filter "source=learned" --json` and confirm the event exists. The full audit-source verification is a manual checkpoint (or an extension of the test that parses the SID from `--print-sid` and runs `audit show`).

### S-86: DNS pinning — single CONNECT per host (automated)

**What:** The proxy resolves the hostname once and dials the resolved IPs directly (never re-resolves). Verify by checking that only one DNS resolution occurs per CONNECT — observable via `SANDBOX_DIAG` logging or by confirming the connection succeeds (the pinned IP is dialed, not a re-resolved hostname). [G-12]

```powershell
# S-86: DNS pinning — single resolution, IP dial (anti-rebinding).
function Invoke-Scenario-S86 {
    $d = New-ScenarioDir 86
    # Run with SANDBOX_DIAG to capture the proxy's DNS pinning log line.
    $r = Invoke-Sandbox -Args @(
        'run','--allow-cwd',
        '--allow-domain','api.anthropic.com',
        '--no-prompt',
        '--','cmd','/c','curl','-s','-o','NUL','-w','%{http_code}',
        'https://api.anthropic.com'
    ) -WorkingDirectory $d -Diag
    $out = ($r.Stdout -join '')
    $err = ($r.Stderr -join "`n")

    # The connection should succeed (200 or 4xx from Anthropic).
    $connectionOk = ($out -match '200') -or ($out -match '4[0-9][0-9]')
    # With SANDBOX_DIAG, the proxy logs the pinned IPs it dials.
    # (This depends on D-1.2's SANDBOX_DIAG logging; if no log line exists,
    # fall back to just verifying the connection succeeded.)
    $pinnedLog = $err -match '(?i)\[proxy\].*pin|resolv|dial.*\d+\.\d+\.\d+\.\d+'

    $passed = $connectionOk
    return @{ Num=86; Name='S-86 (DNS pinning)'; Passed=$passed; Skipped=$false
        Detail = if ($passed) { "connection succeeded (http=$out, pinnedLog=$pinnedLog)" } else { "exit=$($r.ExitCode) stdout=$out stderr=$err" } }
}
```

**Setup:** `--allow-domain api.anthropic.com --no-prompt` with `SANDBOX_DIAG=1`.
**Command:** `curl https://api.anthropic.com`.
**Expected:** Connection succeeds (HTTP 200 or 4xx). The `SANDBOX_DIAG` stderr shows the proxy resolved the host once and dialed the pinned IPs (not a hostname re-resolution).
**Note:** the exact `SANDBOX_DIAG` log format depends on D-1.2's implementation. If no explicit pinning log line was added, the test verifies the connection succeeded (which implicitly confirms the pinned IPs were dialed — a hostname re-dial would also work, so this is a weak test; the strong anti-rebinding verification is the Rust unit test in D-1.2).

### S-87: loopback CONNECT refused via curl -x (automated)

**What:** The proxy refuses CONNECT to any loopback host (`127.0.0.1`, `::1`, `localhost`, `*.localhost`) with `403` + `X-Sandbox: denied`. [G-44] This is the end-to-end version of S-75, but using `curl -x` to force an explicit CONNECT through the proxy.

```powershell
# S-87: loopback CONNECT refused — 403 + X-Sandbox: denied.
function Invoke-Scenario-S87 {
    $d = New-ScenarioDir 87

    # Start a dummy local server on a high port, then try CONNECT to it.
    $listener = [System.Net.Sockets.TcpListener]::new([System.Net.IPAddress]::Loopback, 0)
    $listener.Start()
    $localPort = $listener.LocalEndpoint.Port
    $listener.Stop()

    # Run the sandbox with a proxy. The inner curl uses -x to force a
    # CONNECT through the proxy to 127.0.0.1:<localPort>.
    # SANDBOX_PROXY_PORT is injected by the sandbox env block (D-0.3).
    $r = Invoke-Sandbox -Args @(
        'run','--allow-cwd',
        '--allow-domain','127.0.0.1',
        '--no-prompt',
        '--','cmd','/c','curl','-s','-D','-','-o','NUL',
        '-x','http://127.0.0.1:%SANDBOX_PROXY_PORT%',
        'https://127.0.0.1'
    ) -WorkingDirectory $d -Diag
    $out = ($r.Stdout -join "`n") + ($r.Stderr -join "`n")
    $has403 = $out -match '403'
    $hasHeader = $out -match '(?i)X-Sandbox:\s*denied'
    $passed = $has403 -and $hasHeader
    return @{ Num=87; Name='S-87 (loopback CONNECT refused)'; Passed=$passed; Skipped=$false
        Detail = if ($passed) { 'loopback CONNECT refused (403 + X-Sandbox: denied)' } else { "has403=$has403 hasHeader=$hasHeader out=$out" } }
}
```

**Setup:** A sandbox session with a proxy. `--allow-domain 127.0.0.1 --no-prompt` (the host is in the allow-list, but loopback CONNECT is hard-denied regardless of the allow-list).
**Command:** `curl -x http://127.0.0.1:$SANDBOX_PROXY_PORT https://127.0.0.1` (forces a CONNECT to loopback).
**Expected:** HTTP `403 Forbidden` + `X-Sandbox: denied` header. Audit `source: "hard-deny"`.
**Note:** the `%SANDBOX_PROXY_PORT%` env var is injected by the sandbox's `build_env_block` (D-0.3). If the variable name differs, adjust the test. The `curl -x` flag forces curl to use the proxy, which sends a CONNECT for HTTPS URLs.

### S-88: Proxy-Authorization missing → 407 (automated)

**What:** A request without `Proxy-Authorization: Basic` (or with an invalid token) is rejected with `407 Proxy Authentication Required`. [G-27, G-54]

```powershell
# S-88: Proxy-Authorization missing → 407 Proxy Authentication Required.
function Invoke-Scenario-S88 {
    $d = New-ScenarioDir 88

    # Run the sandbox with a proxy. The inner curl sends a request through
    # the proxy WITHOUT the Proxy-Authorization header (using a dummy -x URL
    # with no credentials).
    $r = Invoke-Sandbox -Args @(
        'run','--allow-cwd',
        '--allow-domain','api.anthropic.com',
        '--no-prompt',
        '--','cmd','/c','curl','-s','-D','-','-o','NUL',
        '-x','http://127.0.0.1:%SANDBOX_PROXY_PORT%',
        'https://api.anthropic.com'
    ) -WorkingDirectory $d -Diag
    $out = ($r.Stdout -join "`n") + ($r.Stderr -join "`n")
    $has407 = $out -match '407'
    $passed = $has407
    return @{ Num=88; Name='S-88 (Proxy-Authorization missing → 407)'; Passed=$passed; Skipped=$false
        Detail = if ($passed) { 'missing Proxy-Authorization → 407' } else { "exit=$($r.ExitCode) out=$out" } }
}
```

**Setup:** A sandbox session with a proxy. `--allow-domain api.anthropic.com --no-prompt`.
**Command:** `curl -x http://127.0.0.1:$SANDBOX_PROXY_PORT https://api.anthropic.com` (no credentials in the proxy URL → no `Proxy-Authorization` header sent).
**Expected:** HTTP `407 Proxy Authentication Required`. The proxy returns this before any allow-list check or DNS resolution.
**Note:** curl normally sends `Proxy-Authorization` only if the proxy URL contains userinfo. Using `-x http://127.0.0.1:PORT` (no `user:pass@`) means no auth header is sent. The proxy's token check (first step of `handle_conn`, after reading headers) returns 407.

### S-89: prompt_overload — 9 concurrent CONNECTs, 8 dialogs + 1 deny (MANUAL)

**What:** When 9 concurrent CONNECT requests for 9 *different* hosts arrive simultaneously, the prompt semaphore (cap 8) allows 8 dialogs to spawn and immediately denies the 9th with `source: "prompt_overload"`. [G-28] This is a manual test because it spawns 8 native TaskDialog windows and requires the user to observe/ dismiss them.

```powershell
# S-89: prompt_overload — 9 concurrent CONNECTs, 8 dialogs + 9th denied.
# MANUAL APPROVAL: spawns 8 native dialogs that the user must observe.
function Invoke-Scenario-S89 {
    $d = New-ScenarioDir 89

    # Run 9 concurrent CONNECTs to 9 different hosts (none in the
    # allow-list, so each triggers a prompt). The prompt semaphore caps
    # at 8 concurrent; the 9th is immediately denied with
    # source: "prompt_overload".
    #
    # We use a batch script that launches 9 curl processes in parallel.
    $hosts = @(
        'h1.example.com','h2.example.com','h3.example.com',
        'h4.example.com','h5.example.com','h6.example.com',
        'h7.example.com','h8.example.com','h9.example.com'
    )
    $script = "@echo off`r`n"
    foreach ($h in $hosts) {
        $script += "start /b curl -s -o NUL -w `"%{http_code} $h`" https://$h`r`n"
    }
    $script += "timeout /t 30 /nobreak > NUL`r`n"
    $scriptPath = Join-Path $d 'concurrent.bat'
    Set-Content -LiteralPath $scriptPath -Value $script -Encoding ASCII

    $r = Invoke-Sandbox -Args @(
        'run','--allow-cwd',
        '--allow-domain','api.anthropic.com',
        '--','cmd','/c',$scriptPath
    ) -WorkingDirectory $d -Diag
    $out = ($r.Stdout -join "`n")
    $err = ($r.Stderr -join "`n")

    # The user should observe 8 dialog windows. The 9th CONNECT should get
    # a 403 (prompt_overload). We verify by checking the audit log for
    # a "prompt_overload" source event.
    # (The audit verification requires the SID — use --print-sid.)
    $hasOverload = $err -match '(?i)prompt_overload|semaphore|overload'

    # This is a manual test: the user confirms they saw 8 dialogs.
    # The automated check is best-effort.
    $passed = $true  # Manual verification overrides this.
    return @{ Num=89; Name='S-89 (prompt_overload 9 concurrent)'; Passed=$passed; Skipped=$false
        Detail = 'MANUAL: verify 8 dialogs appeared + 9th denied (prompt_overload). automated check: ' + $hasOverload }
}
```

**Setup:** A sandbox session WITHOUT `--no-prompt` (prompts enabled). `--allow-domain api.anthropic.com` (none of the 9 test hosts are in the allow-list).
**Command:** 9 concurrent `curl https://h<N>.example.com` processes.
**Expected:** 8 native TaskDialog windows appear (one per host, coalesced by hostname). The 9th concurrent CONNECT (for a *new* host not already being prompted) is immediately denied with `403` + `source: "prompt_overload"`. [G-28]
**Manual verification:** the user confirms:
1. 8 dialog windows appeared (not 9).
2. The 9th request received a 403 (or one of the 8 dialogs' result covered the 9th if it was the same host — but we use 9 *different* hosts to avoid coalescing).
3. The audit log contains an event with `source: "prompt_overload"`.
**Note:** the prompt coalescing ([G-6]) means concurrent requests for the *same* host share one dialog. Using 9 *different* hosts ensures 9 separate dialogs are attempted, hitting the semaphore cap. The semaphore is acquired per-host-prompt, not per-CONNECT.
