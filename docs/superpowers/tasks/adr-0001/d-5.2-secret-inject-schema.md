# Task: D-5.2 — Reserve `secret.inject` event schema

> **ADR:** ADR-0001 §D-5 [G-50]
> **Phase:** 2 (audit)
> **Depends on:** none
> **Blocks:** none (schema reservation only, no emission code)

## Objective

Define the `secret.inject` audit event schema now (documentation + doc comment), so F-2 (credential injection) can emit it without a schema change later. No emission code is written — the event type is reserved in the taxonomy.

## Current state

The audit module (`src/audit/mod.rs`) documents event types in comments and code. There is no `secret.inject` event type today. The F-2 feature (credential injection) is deferred, but defining the schema now avoids a future schema amendment.

## Implementation

### Step 1: Add a doc comment to `src/audit/mod.rs`

After the existing module-level doc comment (lines 1–4), add a section documenting the event taxonomy:

```rust
//! ## Audit event taxonomy
//!
//! | Event | When | Key fields |
//! |---|---|---|
//! | `SESSION_START` | session begins | `sid`, `command`, `disposition` |
//! | `CONNECT` | every network allow/deny | `host`, `port`, `disposition`, `reason`, `source`, `scope`, `persisted` |
//! | `secret.inject` *(reserved, F-2)* | each secret injected into a sidecar/proxy route | `name` (never `value`) |
//!
//! ### `secret.inject` schema (reserved — emission deferred to F-2)
//!
//! ```json
//! {"op":"secret.inject","name":"OPENAI_API_KEY","seq":12,"ts":"2026-07-30T12:00:00Z","hash":"...","parent":"..."}
//! ```
//!
//! **Secret safety:** the `name` field identifies *which* secret was injected
//! (e.g. `"OPENAI_API_KEY"`), never the value. This matches the US-4 posture
//! (DPAPI at rest, never log credentials). Emission begins when F-2 (credential
//! injection) lands; the schema is reserved now so F-2 doesn't need a schema
//! amendment.
```

### Step 2: Add a compile-time doc test

In `src/audit/mod.rs`, add a doc test that verifies the schema is documented:

```rust
/// Verify the `secret.inject` event schema is documented in the module docs.
/// This is a compile-time check — if the doc comment is removed, this test
/// fails to find the schema string.
#[cfg(test)]
#[test]
fn secret_inject_schema_documented() {
    // The module doc comment is not directly accessible at runtime, but we
    // can verify the concept is documented by checking that the source file
    // contains the schema definition.
    let source = include_str!("mod.rs");
    assert!(
        source.contains("secret.inject"),
        "secret.inject event type must be documented in the audit module"
    );
    assert!(
        source.contains("name") && source.contains("never the value"),
        "secret.inject schema must document that only the name is logged, never the value"
    );
}
```

**Note:** `include_str!("mod.rs")` includes the file's own source at compile time. This test verifies the documentation is present. It's a lightweight guard against accidental removal.

### Step 3: Verify

```bash
cargo test -- secret_inject_schema_documented
```

Should pass.
