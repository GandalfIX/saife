# Task: D-0.2 — Remove `loopback.rs` and the downgrade-to-block-net logic

> **ADR:** ADR-0001 §D-0 [G-1, G-58]
> **Phase:** 1 (keystone)
> **Depends on:** D-0.1 (capability SID must be in place first)
> **Blocks:** D-0.5 (un-skip integration tests)

## Objective

Delete the admin-only loopback exemption module (`src/net/loopback.rs`) and the runtime downgrade logic in `src/main.rs` that replaces `NetworkConfig::Allow` with `NetworkConfig::Blocked` when unprivileged. With D-0.1's capability SID, the loopback exemption is no longer needed.

## Current state

### `src/net/loopback.rs` (56 lines, to be deleted entirely)
- `register_loopback(ac_sid: &PSID) -> Result<()>` — calls `NetworkIsolationSetAppContainerConfig`, which is admin-only and system-wide. Returns `Err` unprivileged.

### `src/main.rs` downgrade block (lines 250–267)
```rust
let net_cfg = match &net_cfg_resolved {
    net::NetworkConfig::Allow { .. } => {
        eprintln!("[saife] warning: --allow-domain / --network-profile are deferred ...");
        net::NetworkConfig::Blocked  // <-- downgrade
    }
    other => other.clone(),
};
```
This replaces `Allow` with `Blocked`, printing a multi-line warning. The entire block must be deleted; `net_cfg` should just be `net_cfg_resolved.clone()`.

### `src/main.rs` loopback call (lines 276–281)
```rust
if !net_cfg.is_blocked()
    && let Err(e) = net::loopback::register_loopback(&session.ac_sid)
{
    eprintln!("[saife] warning: loopback exemption failed: {e}");
}
```
This entire block must be deleted.

### `src/net/mod.rs` (line 4)
```rust
pub mod loopback;
```
Delete this line.

## Implementation

### Step 1: Delete `src/net/loopback.rs`

Remove the file entirely:
```bash
git rm src/net/loopback.rs
```

### Step 2: Remove the module declaration

In `src/net/mod.rs`, delete line 4:
```rust
pub mod loopback;
```

### Step 3: Delete the downgrade block in `src/main.rs`

Replace lines 250–267 (the `match` that downgrades `Allow` → `Blocked`) with a simple clone:

```rust
let net_cfg = net_cfg_resolved.clone();
```

Also delete the multi-line comment block at lines 242–249 that explains the deferral — it's no longer accurate.

### Step 4: Delete the `register_loopback` call in `src/main.rs`

Delete lines 276–281 (the `if !net_cfg.is_blocked() { register_loopback(...) }` block).

### Step 5: Update stale CLI comments

In `src/cli.rs`, update the `--block-net` and `--allow-domain` arg doc comments:
- Line 37: `--block-net` — change from `"Block all outbound network (stub for this slice: accepted, logged, ignored)."` to `"Block all outbound network (no proxy, no network capability SIDs, all connect() kernel-denied)."`
- Line 41: `--allow-domain` — change from `"Allow a domain (repeatable) (stub for this slice: accepted, logged, ignored)."` to `"Allow a domain (repeatable). Requires network capability (privateNetworkClientServer SID)."`

### Step 6: Verify

```bash
cargo build --release   # zero warnings (no dangling references to loopback module)
cargo test              # all existing tests pass
```

**Expected warnings to fix:** if any test or code references `net::loopback`, it will fail to compile. The only reference should be the `main.rs` call site (deleted in Step 4) and the `mod.rs` declaration (deleted in Step 2). Grep to verify:

```bash
rg "loopback" src/
```

The only acceptable remaining references are in comments documenting *why* it was removed (if any) or in `setup.rs` (which may still mention "loopback" in a diagnostic string — update that in D-0.4).
