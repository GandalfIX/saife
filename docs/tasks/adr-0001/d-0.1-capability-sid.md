# Task: D-0.1 — Add `privateNetworkClientServer` capability SID to AppContainer spawn

> **ADR:** ADR-0001 §D-0 [G-1, G-21, G-34, G-53, G-58]
> **Phase:** 1 (keystone)
> **Depends on:** none
> **Blocks:** D-0.2, D-0.3, D-0.5, all of Phase 3+

## Objective

Replace the admin-only `NetworkIsolationSetAppContainerConfig` loopback exemption with a `privateNetworkClientServer` capability SID (`S-1-15-3-7`) on the AppContainer token. This is a runtime token attribute (passed to `CreateProcessW` via `PROC_THREAD_ATTRIBUTE_SECURITY_CAPABILITIES`), not a system-wide config call — no admin required.

## Current state

`src/sandbox/spawn.rs` lines 45–49 populate `SECURITY_CAPABILITIES` with `Capabilities = null_mut` and `CapabilityCount = 0`. This means every AppContainer process has zero network capability SIDs — the kernel denies all `connect()` calls. This is correct for `--block-net` but prevents `--allow-domain` from working (the proxy is unreachable).

The capability SID must be added **conditionally**: `Blocked` mode → zero capabilities (current behavior); `Allow` mode → one capability (`privateNetworkClientServer`).

## Implementation

### Step 1: Define the capability SID constant

In `src/sandbox/spawn.rs` (or `src/sandbox/appcontainer.rs` near the existing `ALL_RESTRICTED_APP_PACKAGES_RIDS` pattern at line 24):

```rust
/// S-1-15-3-7 — `privateNetworkClientServer` capability.
/// Grants the AppContainer process loopback + intranet (not public
/// internet) network access. This is the unprivileged replacement for the
/// admin-only `NetworkIsolationSetAppContainerConfig` API.
/// See ADR-0001 §D-0.
const PRIVATE_NETWORK_CLIENT_SERVER_RIDS: [u32; 4] = [15, 3, 0, 7];
```

The SID is `S-1-15-3-7` — identifier authority `15` (security manager), revision `1`, 1 sub-authority `7`. Use `AllocateAndInitializeSid` with `SECURITY_MANDATORY_LABEL_AUTHORITY` (identifier authority `15`).

**Wait — verify the exact SID.** The `privateNetworkClientServer` capability is documented as `S-1-15-3-7`. The identifier authority for capability SIDs is `S-1-15-...` (package SID, revision 1, authority 15, then sub-authorities). Use the `windows` crate's `AllocateAndInitializeSid` with:
- `IdentifierAuthority`: `SID_IDENTIFIER_AUTHORITY { Value: [0,0,0,0,0,15] }` (authority 15)
- `SubAuthorityCount`: 2
- `SubAuthority[0]`: 3
- `SubAuthority[1]`: 7

Actually, capability SIDs follow the pattern `S-1-15-3-<capability>`. For `privateNetworkClientServer` the RID is 7. So the full SID is `S-1-15-3-7` with:
- Revision: `SECURITY_SID_REVISION` (1)
- Authority: `{ Value: [0,0,0,0,0,15] }`
- SubAuthorityCount: 2
- SubAuthority[0]: 3 (capability group)
- SubAuthority[1]: 7 (`privateNetworkClientServer`)

### Step 2: Build the `SID_AND_ATTRIBUTES` array

Add a helper function in `src/sandbox/appcontainer.rs` (alongside the existing `well_known_sid` / `builtin_admins_sid` helpers):

```rust
use windows::Win32::Security::{
    AllocateAndInitializeSid, FreeSid, SID, SID_AND_ATTRIBUTES,
    SID_IDENTIFIER_AUTHORITY, SecurityCapability,
};

/// Allocate the `privateNetworkClientServer` capability SID (`S-1-15-3-7`).
/// Returns a raw `PSID` that must be freed with `FreeSid` by the caller.
/// Returns `None` if the SID allocation fails (should not happen on any
/// supported Windows build).
fn allocate_private_network_capability_sid() -> Option<PSID> {
    let authority = SID_IDENTIFIER_AUTHORITY { Value: [0, 0, 0, 0, 0, 15] };
    let mut sid_ptr: PSID = std::ptr::null_mut();
    let sub_authorities: [u32; 2] = [3, 7]; // S-1-15-3-7
    unsafe {
        if AllocateAndInitializeSid(
            &authority,
            sub_authorities.len() as u8,
            sub_authorities[0],
            sub_authorities[1],
            0, 0, 0, 0, 0, 0,
            &mut sid_ptr,
        ).is_ok()
        {
            Some(sid_ptr)
        } else {
            None
        }
    }
}
```

**Note:** verify `AllocateAndInitializeSid` signature in the `windows` crate v0.62. The function takes `&SID_IDENTIFIER_AUTHORITY`, then `sub_authority_count: u8`, then up to 8 sub-authority `u32` values, then `*mut PSID`. Unused sub-authority slots are passed as `0`.

### Step 3: Populate `SECURITY_CAPABILITIES` in spawn

Modify the `spawn` function signature to accept a `network_active: bool` parameter (or a `&NetworkConfig` reference). When `network_active` is true, populate the capabilities array:

```rust
pub fn spawn(
    session: &AppContainerSession,
    job: &Job,
    cwd: &std::path::Path,
    env_block: Vec<u16>,
    cmdline: &str,
    network_active: bool,   // <-- new parameter
) -> Result<u32> {
```

Inside the function, before the `SECURITY_CAPABILITIES` struct is built (line 45):

```rust
// Allocate the capability SID if network is active. The SID must
// outlive CreateProcessW, so it's held in a local.
let cap_sid: Option<PSID> = if network_active {
    crate::sandbox::appcontainer::allocate_private_network_capability_sid()
} else {
    None
};

let mut cap_attrs: [SID_AND_ATTRIBUTES; 1] = [SID_AND_ATTRIBUTES {
    Sid: cap_sid.unwrap_or(std::ptr::null_mut()),
    Attributes: 0, // capabilities use SE_GROUP_ENABLED implicitly
}];

let (caps_ptr, caps_count) = if network_active {
    (cap_attrs.as_mut_ptr() as *mut _, 1)
} else {
    (std::ptr::null_mut(), 0)
};

let mut sec_caps = SECURITY_CAPABILITIES {
    AppContainerSid: session.ac_sid,
    Capabilities: caps_ptr,
    CapabilityCount: caps_count,
    Reserved: 0,
};
```

**Important:** the `cap_sid` and `cap_attrs` locals must live until after `CreateProcessW` returns (line 83). They are on the stack frame, so they're valid for the entire `unsafe` block. Free the SID after `DeleteProcThreadAttributeList` (line 85):

```rust
// Free the capability SID after CreateProcessW has consumed it.
if let Some(sid) = cap_sid {
    unsafe { let _ = FreeSid(sid); }
}
```
