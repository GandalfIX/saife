# Task: D-5.1 — Add `source`/`scope`/`persisted` fields to the CONNECT audit event

> **ADR:** ADR-0001 §D-5 [G-9, G-31]
> **Phase:** 2 (audit, no dependencies on Phase 1)
> **Depends on:** none (can be done in parallel with Phase 1)
> **Blocks:** D-5.4 (filter keys)

## Objective

Augment the existing `CONNECT` audit event with three new fields: `source` (enum), `scope` (nullable string), `persisted` (bool). These enable greppable attribution of why a network decision was made, without parsing free-text `reason` fields.

## Implementation

### Step 1: Define the `source` enum values

In `src/net/proxy.rs`, add a const array for documentation and a `NetSource` enum:

```rust
/// Audit `source` field values for CONNECT events. Identifies which
/// pipeline stage produced the allow/deny decision.
/// See ADR-0001 §D-5 [G-9].
pub const NET_SOURCE_VALUES: &[&str] = &[
    "hard-deny",       // metadata/link-local IP or hostname
    "learned",         // learned-policy file (permanent decision)
    "blocklist",       // deny_domain blocklist match
    "allowlist",       // allow_domain or learned permanent allow
    "prompt",          // interactive prompt decision
    "unavailable",     // prompt enabled but no USER DECISION: the budget
                       // elapsed, no dialog backend exists, or the caller went
                       // away. `reason` names which — see the token list below.
    "dns",             // DNS resolution failure
    "default",         // no prompt, default deny/allow
    "prompt_overload", // a capacity pool refused the consultation (P2.1: which
                       // one is in `reason`, not in `source`)
];
```

#### `reason` tokens for `source: "unavailable"` and `"prompt_overload"` (P2.1)

`source` says which pipeline stage decided; `reason` says why. Before P2.1 both
non-decision outcomes were prose that conflated two causes each, so a reader could
not tell a spent budget from a missing dialog backend, nor an exhausted
consultation pool from a full pool of abandoned dialogs. The tokens are stable and
greppable, and `reason` is a filterable key (`saife audit show --filter
"reason=no_dialog_backend"`):

| token | `source` | meaning | remediation |
| --- | --- | --- | --- |
| `prompt_budget_exhausted` | `unavailable` | the consultation's budget elapsed with no answer; the dialog is abandoned and its late click is discarded ([G-4], [G-46]). Both legs (CONNECT and the absolute-form forward) produce it. | answer the dialog, raise `network.promptTimeoutSecs`, or pre-approve the host |
| `no_dialog_backend` | `unavailable` | no dialog could produce a decision: the backend failed ([G-19]), **or** the fast-fail latch is armed and it was armed by consultations that found no dialog at all (`NO_BACKEND_STICKY_AFTER`, 3 consecutive) | run interactively, or set `onUnavailable`/`--allow-domain` deliberately |
| `prompt_suppressed_after_budget` | `unavailable` | the fast-fail latch is armed and it was armed by consultations whose budgets ELAPSED with the dialog up: the backend demonstrably works and nobody answered, so this session stops paying per host. Deny posture only, and the latch re-probes after `NO_BACKEND_REPROBE_COOLDOWN` (10 min) | be at the desk, raise `network.promptTimeoutSecs`, or pre-approve the host |
| `prompt_abandoned_capacity` | `prompt_overload` | the abandoned pool (`MAX_ABANDONED_PROMPTS`, 16) is full: dialogs from earlier consultations are still on screen | answer or dismiss the dialogs already up |
| `too many concurrent prompts` | `prompt_overload` | all `MAX_CONCURRENT_PROMPTS` (8) consultation slots are in flight ([G-28]) | reduce concurrency, or answer a dialog |

`caller_gone` (the leader's caller vanished and its outcome was fanned out to parked
followers) stays prose — `prompt unavailable (caller gone)` — because it is not a
prompt policy fact at all: the dialog may be on screen and working.

## `SESSION_START` — the session's chain root (P2.3)

Every **run** writes **exactly one** `SESSION_START` leaf: `audit verify` needs
non-zero leaves to recompute a root, and under `--block-net` no proxy starts, so no
CONNECT leaf can exist. ADR-0004 guardrail 2 puts the per-session tier facts
**here** rather than on every CONNECT leaf.

The guarantee is one root **per run**, and it is guaranteed against the **child**:
the leaf is written before the child is spawned (`src/main.rs:748` versus `:767`),
and every early return between arming and writing it falls back to the same leaf.
It is *not* "always the genesis leaf", which is what this section used to claim:

* the listener is bound **before** the root is written (`src/main.rs:717` starts
  the proxy, `:748` writes the leaf), so a local connection that reaches that
  listener inside the window is audited by the proxy thread first and the run's
  root then lands at `seq > 0`;
* a reused `--sid` opens the existing chain (`AuditWriter::open` continues from
  `scan_existing`), so a second run legitimately appends a second root at
  `seq > 0` — two runs, two roots, and `verify` still links.

A hard `TerminateProcess`/abort skips `Drop` and lands no root at all. And a
**non-strict** writer swallows a failed write (`AuditWriter::append` returns
`Ok(())` when the file cannot be opened or written), so "one root" holds except
when the sink refuses — then the run proceeds with no root. `--audit-strict` is
the fail-closed mode.

| key | type | meaning |
|---|---|---|
| `op` | `"SESSION_START"` | the root |
| `sid` | string | session id |
| `command` | string | the workload command line, joined |
| `disposition` | `"allow"` \| `"deny"` | `allow` on the success and fallback paths; `deny` on a **refused** session's root, so the root never claims a start the next leaf denies |
| `tier` | string \| null | `base-container` \| `appcontainer-dacl` \| `null` = unknown |
| `tier_source` | string \| null | `probe` \| `unavailable` \| `structural` \| `null` = unknown |
| `tier_needs_dacl_augmentation` | bool \| null | verbatim from the probe; `null` when nothing stated it |
| `elevated` | bool \| null | whether the **supervisor** process ran elevated |
| `proxy_endpoint` | `"127.0.0.1:<port>"` \| null | this run's listener; `null` under `--block-net` |

```json
{"op":"SESSION_START","sid":"20261022-113501-00042","command":"cmd /c echo hi","disposition":"allow","tier":"appcontainer-dacl","tier_source":"structural","tier_needs_dacl_augmentation":true,"elevated":true,"proxy_endpoint":"127.0.0.1:51764","seq":0,"ts":"2026-10-22T09:35:01Z","hash":"…","parent":null}
```

All five fact keys are always **present**; a `null` means only that the value was
not established. A consumer must read `null` as *unknown*, never as "no".

What a run that ends early records (P2.3 review): the tier and the elevation are
knowable **before** the launch — the AppContainer backend *is* its tier, and
`elevated` is one token query — so the `Drop` fallback writes them, and only
`proxy_endpoint` is `null` (no listener was bound). An early-death session is
therefore still selectable by `tier=appcontainer-dacl` and by `elevated=false`,
which is exactly the session an incident reader is looking for. The armed facts
are what the guard carries; `complete` adds the endpoint.

### `tier_source`: three values

| value | when | what it does **not** claim |
|---|---|---|
| `probe` | `v1::probe` on the exact request named the tier (MXC) | nothing about tiers the probe did not evaluate |
| `unavailable` | the probe ran and named no tier (MXC) — `tier` is then `null` | not "no tier", and never the backend ceiling (ADR-0004 forbids recording a ceiling as the dispatched tier) |
| `structural` | the backend **is** the tier by construction, so there was nothing to probe (P2.3 — the AppContainer backend: it creates the profile and grants the host DACLs itself) | not a dispatch decision; `probe` here would be a lie |

`tier` and `tier_source` travel together: a leaf may not name a tier without
saying how it is known.

**Three values, not four.** `null` is *absence* — nothing established it — not a
fourth case beside them. Consumers compare **`tier`** (`tier=base-container`,
`tier=null` for a run that could not name one) and read `tier_source` only as the
explanation of how that value is known.

### `proxy_endpoint` carries no credential

The child's proxy URL is `http://sandbox:<token>@127.0.0.1:<port>` and that
userinfo is this run's credential — the value the listener refuses every other
holder of. The leaf records **`127.0.0.1:<port>` only**.

The real guarantee (P2.3 review; the earlier claim "a URL cannot be passed at
all" was only true of a helper function, while `SessionStartFacts`' fields were
public):

* `proxy_endpoint: Option<LoopbackEndpoint>`, a newtype over a **private** `u16`;
* its only constructor is `LoopbackEndpoint::new(port: u16)` — no `From<String>`,
  no `FromStr`, no field access;
* `SessionStartFacts`' fields are private, with named constructors and no
  `Default`, so a struct literal — with a URL in it or with facts left out —
  does not compile outside the module.

Rendered value for port 49152 is exactly `127.0.0.1:49152` (no scheme, no
userinfo, no path). Pinned by `the_leaf_carries_no_credential` (no `@`, no
`sandbox:`, no token substring anywhere in the chain) and
`the_endpoint_renders_as_the_bare_loopback_authority`.

### `SESSION_REFUSED` — a guardrail ended the session before any child ran

```json
{"op":"SESSION_REFUSED","sid":"…","disposition":"deny","reason":"tier_mismatch","expected_tier":"base-container","seq":1,"ts":"…","hash":"…","parent":"<hash of the SESSION_START root>"}
```

The root above it names the tier that was **actually** dispatched, so a degraded
tier stays visible after the fact even though the session was refused (ADR-0004
guardrail 2's hard half). No CONNECT leaf can follow: guardrail 2 runs before the
launch epoch opens and before the child exists
(`net::mxc::verify_tier`), and the live test
`a_wrong_tier_refuses_the_session_with_no_connect_leaves` asserts the chain is
root + refusal with the listener's counters at `{0,0}`. `reason` and
`expected_tier` are filterable keys.

All six session-start keys and `expected_tier` are in
`audit::filter::KNOWN_KEYS`: `tier`/`tier_source`/`expected_tier` match
case-sensitively (enum-like taxonomy values), `elevated` and
`tier_needs_dacl_augmentation` compare as booleans (`=true` / `=false`), and
`proxy_endpoint` matches like a host. So an incident reader can ask
`saife audit show <sid> --filter "tier=appcontainer-dacl"` and get the roots of
the sessions that ran degraded.

`=null` is a value for **every** key and means "this leaf's value is JSON null",
which is how a leaf says *nothing was established here*:

| query | selects |
|---|---|
| `tier=null` | a root that could not name its tier |
| `elevated=null` | a root that could not measure elevation |
| `proxy_endpoint=null` | every `--block-net` session, and every early death |

For a boolean key, `null` is **not** a synonym for `false`: `elevated=false` is an
unelevated run, `elevated=null` is an unmeasured one. Any other value for a
boolean key (`elevated=yes`, `persisted=1`) is a **parse error** rather than a
silent coercion — before the review every value except `true` was read as
`false`, so `elevated=yes` answered with every *unelevated* run.
