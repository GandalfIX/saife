# Task: D-5.3 — Add `--audit-strict` flag

> **ADR:** ADR-0001 §D-5 [G-13]
> **Phase:** 2 (audit)
> **Depends on:** none
> **Blocks:** Checkpoint 2

## Objective

Add an `--audit-strict` flag that puts the audit writer in fail-closed mode: refuse to start if the log can't be opened, abort the run if a write fails mid-session. Default is **off** (fail-open, matching omac). The default flips to fail-closed when F-2 lands.

## Current state

### `AuditWriter` (`src/audit/mod.rs`)
- `open(session_id: &str) -> Self` — opens the log at `%LOCALAPPDATA%\sandbox\audit\<sid>.ndjson`. Never fails (returns a `Self` even if the file can't be opened — writes silently fail).
- `append(&self, event: Map<String, Value>)` — writes a line. Errors are silently ignored (`let _ = f.write_all(...)`). No strict mode.

### CLI (`src/cli.rs`)
No `--audit-strict` flag exists.

### Step 3: Update `open` to accept `strict`

Change `open` to `open_with_strict` (or add a new constructor):

```rust
impl AuditWriter {
    pub fn open(session_id: &str) -> Self {
        Self::open_with_strict(session_id, false)
    }

    pub fn open_with_strict(session_id: &str, strict: bool) -> Self {
        let path = audit_log_path(session_id);
        let (last_hash, next_seq) = if path.exists() {
            scan_existing(&path).unwrap_or((None, 0))
        } else {
            (None, 0)
        };

        if strict {
            // Verify the log is writable by attempting to create/append.
            if let Err(e) = std::fs::OpenOptions::new()
                .append(true)
                .create(true)
                .open(&path)
            {
                // In strict mode, this is fatal.
                eprintln!("[sandbox] FATAL (--audit-strict): cannot open audit log at {}: {e}", path.display());
                // We can't return an Err from open() since it returns Self.
                // Options: panic (bad), or return a writer that always fails
                // on append. The cleanest approach is to change open() to
                // return Result<Self>. But that's a bigger refactor.
                //
                // For now: panic with a clear message. The caller (main.rs)
                // should check before calling open, or we refactor to
                // return Result.
                panic!("[sandbox] --audit-strict: cannot open audit log: {e}");
            }
        }

        Self {
            path,
            last_hash: Mutex::new(last_hash),
            seq: AtomicU64::new(next_seq),
            strict,
        }
    }
}
```

**Better approach:** change `AuditWriter::open` to return `Result<Self>` and have `main.rs` handle the error. This is a small refactor:

```rust
pub fn open_with_strict(session_id: &str, strict: bool) -> anyhow::Result<Self> {
    let path = audit_log_path(session_id);
    // ... scan existing ...

    if strict {
        std::fs::OpenOptions::new()
            .append(true)
            .create(true)
            .open(&path)
            .context("cannot open audit log (--audit-strict)")?;
    }

    Ok(Self { path, last_hash: Mutex::new(last_hash), seq: AtomicU64::new(next_seq), strict })
}
```

Then in `main.rs`, replace `AuditWriter::open(&sid)` with:
```rust
let audit_writer = AuditWriter::open_with_strict(&sid, audit_strict)
    .context("open audit log")?;
```

Keep `open(session_id)` as a convenience wrapper for non-strict (used by tests):
```rust
pub fn open(session_id: &str) -> Self {
    Self::open_with_strict(session_id, false).unwrap_or_else(|_| Self {
        path: audit_log_path(session_id),
        last_hash: Mutex::new(None),
        seq: AtomicU64::new(0),
        strict: false,
    })
}
```

### Step 4: Update `append` to respect strict mode

```rust
pub fn append(&self, mut event: Map<String, Value>) {
    // ... compute seq, ts, hash, parent ...

    let write_result = std::fs::OpenOptions::new()
        .append(true)
        .create(true)
        .open(&self.path)
        .and_then(|mut f| f.write_all(line.as_bytes()));

    match write_result {
        Ok(_) => {
            *self.last_hash.lock().unwrap() = Some(hash);
        }
        Err(e) => {
            if self.strict {
                eprintln!("[sandbox] FATAL (--audit-strict): audit write failed: {e}");
                // Abort the process. The sandboxed child may still be running;
                // we need to kill it and exit.
                std::process::exit(7); // exit code 7 = sandbox process error
            } else {
                eprintln!("[sandbox] warning: audit write failed: {e} (fail-open; run continues)");
            }
        }
    }
}
```

**Note on the `std::process::exit` in `append`:** this is aggressive but correct for strict mode — an unrecorded run is unacceptable. The alternative (returning `Result` from `append`) would require changing all callers to handle the error, which is a larger refactor. For now, `process::exit` is acceptable; a future refactor can make `append` return `Result<()>`.

### Step 6: Add unit tests

mod tests {

    #[test]
    fn strict_mode_refuses_unwritable_path() {
        // Point LOCALAPPDATA at a non-existent directory.
        std::env::set_var("LOCALAPPDATA", "/nonexistent/path/that/does/not/exist");
        let result = AuditWriter::open_with_strict("test-strict", true);
        assert!(result.is_err());
        std::env::remove_var("LOCALAPPDATA");
    }

    #[test]
    fn non_strict_mode_succeeds_on_normal_path() {
        let result = AuditWriter::open_with_strict("test-nonstrict", false);
        assert!(result.is_ok());
        // Clean up
        let _ = std::fs::remove_file(audit_log_path("test-nonstrict"));
    }
}
