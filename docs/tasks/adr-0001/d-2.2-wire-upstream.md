# Task: D-2.2 — Wire upstream dialer into proxy

> **ADR:** ADR-0001 §D-2 [G-10, G-22, G-24, G-30, G-42, G-49]
> **Phase:** 4 (upstream chaining)
> **Depends on:** D-2.1 (upstream dialer), D-0.3 (Proxy-Authorization Basic), D-3.6 (proxy pipeline restructure)
> **Blocks:** D-2.3 (integration tests)

## Objective

Wire `UpstreamDialer` into the proxy's dial path. Extract the inline `TcpStream::connect` calls in `handle_conn` into a single `dial_upstream` function that branches: if an upstream dialer is configured AND `chains_host(host)`, delegate to `UpstreamDialer::dial` (hostname-only, no DNS); otherwise use `DirectDialer` with pinned IPs + Happy Eyeballs. Map `UpstreamError` to a `502 Bad Gateway` response with an `X-Sandbox: upstream-error` header (credentials redacted). In `main.rs`, detect the upstream proxy from profile `network.upstreamProxy` first, then host env `HTTPS_PROXY`/`HTTP_PROXY`, emitting a `SAIFE_DIAG` warning if both are set and differ [G-42].

### Step 4: Extract `dial_upstream` branch in the proxy

After D-3.6 restructures `handle_conn` into the D-1 pipeline with a `dial_and_splice` helper, modify `dial_and_splice` to branch on the upstream dialer. Replace the body of `dial_and_splice` (the current inline `happy_eyeballs_dial` call):

```rust
/// Dial the target, branching on upstream chaining. [G-22, G-24, G-49]
///
/// - If `upstream` is configured and `chains_host(host)`: dial through
///   the upstream proxy (CONNECT-only, hostname-only, no DNS pinning). [G-24]
/// - Otherwise: dial the pinned IPs directly with Happy Eyeballs. [G-12]
///
/// Returns the established `TcpStream` or an `UpstreamError`-shaped error.
async fn dial_upstream(
    upstream: &Option<crate::net::upstream::UpstreamDialer>,
    host: &str,
    port: u16,
    pinned_addrs: &[IpAddr],
) -> Result<TcpStream, DialError> {
    match upstream {
        Some(u) if u.chains_host(host) => {
            // [G-22] Skip local DNS under chaining — pass empty pinned_addrs.
            u.dial(host, port, &[])
                .await
                .map_err(DialError::Upstream)
        }
        _ => {
            // Direct dial with pinned IPs + Happy Eyeballs. [G-12, G-49]
            let direct = crate::net::upstream::DirectDialer::new();
            direct.dial(host, port, pinned_addrs)
                .await
                .map_err(DialError::Direct)
        }
    }
}

enum DialError {
    Upstream(crate::net::upstream::UpstreamError),
    Direct(std::io::Error),
}
```

**[G-22]** Under upstream chaining, skip local DNS resolution: pass `&[]` for `pinned_addrs`. The upstream proxy performs its own DNS. The hostname-based hard-deny list (step 1 of the pipeline) still catches known-bad metadata names regardless of chaining.

**[G-49]** Both dial paths preserved: NO_PROXY matches dial direct (with pinned IPs + Happy Eyeballs); non-matches chain through upstream. Mutually exclusive per-request.

### Step 5: Handle `UpstreamError` → 502 response

In `dial_and_splice` (or wherever the dial result is consumed), map `DialError::Upstream` to a `502 Bad Gateway` with `X-Sandbox: upstream-error` header and a redacted body:

```rust
let upstream_stream = match dial_upstream(&upstream, &host, port, &resolved).await {
    Ok(s) => s,
    Err(DialError::Upstream(e)) => {
        // [G-30] Redact credentials: only proxy host:port in the body.
        let body = e.redacted_message();
        let resp = format!(
            "HTTP/1.1 502 Bad Gateway\r\nX-Sandbox: upstream-error\r\nContent-Length: {}\r\n\r\n{}",
            body.len(), body
        );
        let _ = sock.write_all(resp.as_bytes()).await;
        emit_connect_full(&writer, &host, port, "deny", "upstream-error", None, false);
        return Ok(());
    }
    Err(DialError::Direct(e)) => {
        let _ = sock.write_all(b"HTTP/1.1 502 Bad Gateway\r\nContent-Length: 0\r\n\r\n").await;
        eprintln!("[proxy] direct dial to {host}:{port} failed: {e}");
        return Ok(());
    }
};
```

**[G-30]** Error bodies never include credentials — only the proxy host:port (via `UpstreamError::redacted_message`).

### Step 7: Detect the upstream proxy in `main.rs`

In `src/main.rs` `run_inner` (around line 250, after resolving the network config), detect the upstream proxy with precedence [G-10]: profile `network.upstreamProxy` > host env `HTTPS_PROXY`/`HTTP_PROXY` > none.

```rust
// [G-10] Precedence: profile upstreamProxy > host env HTTPS_PROXY/HTTP_PROXY > none.
// [G-42] Warn on override: if both profile and host env are set and differ.
let upstream: Option<crate::net::upstream::UpstreamDialer> = {
    let profile_upstream = net_cfg_upstream_proxy.as_deref();  // from NetworkSlice
    let host_https = std::env::var_os("HTTPS_PROXY")
        .map(|s| s.to_string_lossy().to_string());
    let host_http = std::env::var_os("HTTP_PROXY")
        .map(|s| s.to_string_lossy().to_string());
    let host_env = host_https.or(host_http);

    let (chosen, source) = match (profile_upstream, &host_env) {
        (Some(p), _) => (Some(p.to_string()), "profile"),
        (None, Some(h)) => (Some(h.clone()), "host-env"),
        (None, None) => (None, "none"),
    };

    // [G-42] Warn if both set and differ.
    if let (Some(p), Some(h)) = (profile_upstream, &host_env) {
        if p != h {
            eprintln!(
                "[saife] SAIFE_DIAG: profile upstreamProxy ({p}) differs from host {HTTPS_PROXY}/{HTTP_PROXY} ({h}); using profile value."
            );
        }
    }

    match chosen {
        Some(url) => {
            // NO_PROXY from profile (CLI merge handled in resolve_network).
            let no_proxy = net_cfg_no_proxy.clone();
            Some(crate::net::upstream::UpstreamDialer::new(&url, no_proxy)
                .with_context(|| format!("configure upstream proxy: {url}"))?)
        }
        None => None,
    }
};
```

**[G-10]** The host env vars are read at launch and never forwarded to the child. The child always gets our loopback-only `HTTP_PROXY`/`HTTPS_PROXY` + `NO_PROXY=localhost,127.0.0.1,::1` (set in D-0.3's `build_env_block`).

**[G-42]** The `SAIFE_DIAG` warning fires only when both profile and host env are set AND differ. When only the host env is set (no profile upstreamProxy), no warning — silent detection.
