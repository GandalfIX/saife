# Task: D-1.1 — Verify pipeline ordering

> **ADR:** ADR-0001 §D-1 [G-18, G-32, G-33, G-45]
> **Phase:** 5 (D-1 finalization — integrates everything after D-0)
> **Depends on:** D-3.2 (matcher expansion), D-3.3 (learned store), D-3.6 (proxy pipeline restructure)
> **Blocks:** D-1.2 (DNS pinning + Happy Eyeballs), D-1.3 (comprehensive tests)

## Objective

Audit the `handle_conn` flow in `src/net/proxy.rs` to confirm the exact 5-stage pipeline order from ADR [G-33], and add a Rust integration test that mocks the filter components to verify ordering: a host in both `deny_domain` and `allow_domain` is denied with `source: "blocklist"`; a host both learned-deny and in `deny_domain` is denied with `source: "learned"` (the user's explicit past decision is more informative than the blocklist match). The pipeline is load-bearing for audit `source` attribution.

## Current state

After D-3.6, `handle_conn` in `src/net/proxy.rs` implements the full D-1 pipeline. The intended order (from ADR §D-1 [G-33]) is:

1. **Hard-deny** (hostname set + IP set + link-local CIDR) — never promptable, overrides everything. [G-18, G-45]
2. **Learned permanent deny** (from the persisted learned-policy file). [G-33]
3. **`deny_domain` blocklist** match. [G-32]
4. **Allow** (`allow_domain` or learned permanent allow). [G-55]
5. **Default** (prompt / `on_unavailable`).

The matcher module (`src/net/matcher.rs`) has the current `check` function (line 110) which does: `is_always_denied` (step 1) → `allow_list` match (step 4) → default deny. This is the **old** 3-stage pipeline (no `deny_list`, no learned). After D-3.2, `check` is expanded and `handle_conn` calls into the stages explicitly.

**The risk:** if steps 2 and 3 are ordered wrong (deny_domain checked before learned-deny), a host that was both learned-denied AND blocklisted would report `source: "blocklist"` instead of `source: "learned"`. The ADR mandates that the user's explicit past decision (`learned`) is more informative and must take precedence in attribution. [G-33]

## Implementation

### Step 1: Audit the pipeline order in `handle_conn`

Read `src/net/proxy.rs` `handle_conn` (post-D-3.6) and verify the exact ordering of the 5 stages. The pipeline must be:

```rust
// --- D-1 pipeline ([G-33]) ---

// Step 1: hard-deny (hostname set + IP set + link-local CIDR). [G-18, G-45]
if crate::net::matcher::is_hard_denied_host(&host) {
    return deny_403(&mut sock, &writer, &host, port, "hard-deny", "denied_dns").await;
}
for ip in &resolved {
    if crate::net::matcher::is_hard_denied_ip(*ip) {
        return deny_403(&mut sock, &writer, &host, port, "hard-deny", "denied_cidr").await;
    }
}

// Step 2: learned permanent deny. [G-33] — BEFORE deny_domain (step 3).
let learned_guard = learned.lock().await;
if let Some(decision) = learned_guard.lookup(&host) {
    if !decision.allow {
        drop(learned_guard);
        return deny_403(&mut sock, &writer, &host, port, "learned", "learned_deny").await;
    }
    // Learned allow — fall through to dial (step 4 allow path).
    drop(learned_guard);
    emit_connect_full(&writer, &host, port, "allow", "learned", Some(&decision.scope), true);
    return dial_and_splice(/* ... */).await;
}
drop(learned_guard);

// Step 3: deny_domain blocklist. [G-32] — AFTER learned-deny (step 2).
if deny.iter().any(|e| crate::net::matcher::matches(&host, e)) {
    return deny_403(&mut sock, &writer, &host, port, "blocklist", "denied_domain").await;
}

// Step 4: allow_domain / learned-allow.
if allow.iter().any(|e| crate::net::matcher::matches(&host, e)) {
    emit_connect_full(&writer, &host, port, "allow", "allowlist", None, false);
    return dial_and_splice(/* ... */).await;
}

// Step 5: default — prompt or on_unavailable.
// ... prompt path ...
```

**Key invariant:** step 2 (learned-deny) MUST appear before step 3 (deny_domain). If they are swapped, the audit `source` attribution is wrong for hosts that are both learned-denied and blocklisted. [G-33]

### Step 2: Add a `pipeline_order` test module

Add a Rust integration test (in `src/net/proxy.rs` under `#[cfg(test)]` or in a separate `tests/pipeline_order.rs`) that mocks the filter components and verifies the two key ordering invariants:

**Test A — deny_domain over allow_domain:** a host in both `deny_domain` and `allow_domain` is denied with `source: "blocklist"`. This verifies step 3 is before step 4. [G-32, G-33]

**Test B — learned-deny over deny_domain:** a host that is both learned-denied and in `deny_domain` is denied with `source: "learned"`. This verifies step 2 is before step 3. [G-33]

Since the full `handle_conn` is async and depends on a `TcpStream`, the cleanest approach is to extract the pipeline decision logic into a testable pure function and test that:

```rust
/// The pure decision part of the pipeline (no I/O). Extracted for testing.
/// Returns `(disposition, source, reason)` — the same fields that go into
/// the audit event and the 403/200 response.
///
/// This does NOT include the prompt path (step 5) — that requires I/O.
/// For unclassified hosts, returns `("deny", "default", "no_match")` —
/// the caller decides whether to prompt or apply on_unavailable.
pub fn pipeline_decision(
    host: &str,
    resolved_ips: &[IpAddr],
    allow_list: &[String],
    deny_list: &[String],
    learned: &crate::net::learned::LearnedStore,
) -> PipelineOutcome {
    // Step 1: hard-deny.
    if crate::net::matcher::is_hard_denied_host(host) {
        return PipelineOutcome::Deny { source: "hard-deny", reason: "denied_dns" };
    }
    for ip in resolved_ips {
        if crate::net::matcher::is_hard_denied_ip(*ip) {
            return PipelineOutcome::Deny { source: "hard-deny", reason: "denied_cidr" };
        }
    }

    // Step 2: learned permanent deny/allow.
    if let Some(decision) = learned.lookup_sync(host) {
        if !decision.allow {
            return PipelineOutcome::Deny { source: "learned", reason: "learned_deny" };
        }
        return PipelineOutcome::Allow { source: "learned", scope: decision.scope, persisted: true };
    }

    // Step 3: deny_domain blocklist.
    if deny_list.iter().any(|e| crate::net::matcher::matches(host, e)) {
        return PipelineOutcome::Deny { source: "blocklist", reason: "denied_domain" };
    }

    // Step 4: allow_domain.
    if allow_list.iter().any(|e| crate::net::matcher::matches(host, e)) {
        return PipelineOutcome::Allow { source: "allowlist", scope: None, persisted: false };
    }

    // Step 5: default — unclassified (caller decides: prompt or on_unavailable).
    PipelineOutcome::Unclassified
}

pub enum PipelineOutcome {
    Allow { source: &'static str, scope: Option<String>, persisted: bool },
    Deny { source: &'static str, reason: &'static str },
    Unclassified,
}
```

**Note:** `learned.lookup_sync` is a synchronous version of `LearnedStore::lookup` (the store holds a `RwLock<HashMap>`; a sync read lock is fine for the test). If `LearnedStore` only exposes `async fn lookup`, the test uses `tokio::test` + `.await`.

### Step 3: Write the tests

```rust
#[cfg(test)]
mod pipeline_tests {
    use super::*;
    use crate::net::learned::{LearnedStore, LearnedEntry};
    use std::net::IpAddr;

    /// Test A: deny_domain over allow_domain → source: "blocklist". [G-32, G-33]
    #[test]
    fn deny_domain_precedence_over_allow() {
        let mut learned = LearnedStore::new();
        // No learned entry for this host.
        let host = "evil.example.com";
        let allow = vec!["*.evil.com".to_string()];
        let deny = vec!["*.evil.com".to_string()];
        let resolved: Vec<IpAddr> = vec![];

        let outcome = pipeline_decision(host, &resolved, &allow, &deny, &learned);
        match outcome {
            PipelineOutcome::Deny { source, reason } => {
                assert_eq!(source, "blocklist");
                assert_eq!(reason, "denied_domain");
            }
            other => panic!("expected Deny(blocklist), got {other:?}"),
        }
    }

    /// Test B: learned-deny over deny_domain → source: "learned". [G-33]
    #[test]
    fn learned_deny_precedence_over_blocklist() {
        let mut learned = LearnedStore::new();
        // Pre-populate a learned DENY for this host.
        learned.insert_sync("evil.example.com", LearnedEntry {
            allow: false,
            scope: "host".to_string(),
        });

        let host = "evil.example.com";
        let allow = vec!["*.evil.com".to_string()];
        let deny = vec!["*.evil.com".to_string()];
        let resolved: Vec<IpAddr> = vec![];

        let outcome = pipeline_decision(host, &resolved, &allow, &deny, &learned);
        match outcome {
            PipelineOutcome::Deny { source, reason } => {
                assert_eq!(source, "learned");
                assert_eq!(reason, "learned_deny");
            }
            other => panic!("expected Deny(learned), got {other:?}"),
        }
    }

    /// Test C: hard-deny overrides everything (learned-allow + deny_domain + allow_domain).
    /// [G-18, G-45]
    #[test]
    fn hard_deny_overrides_all() {
        let mut learned = LearnedStore::new();
        // Even if learned-allowed and in allow_domain, hard-deny wins.
        learned.insert_sync("169.254.169.254", LearnedEntry {
            allow: true,
            scope: "host".to_string(),
        });

        let host = "169.254.169.254";
        let allow = vec!["169.254.169.254".to_string()];
        let deny: Vec<String> = vec![];
        let resolved: Vec<IpAddr> = vec![IpAddr::V4("169.254.169.254".parse().unwrap())];

        let outcome = pipeline_decision(host, &resolved, &allow, &deny, &learned);
        match outcome {
            PipelineOutcome::Deny { source, reason } => {
                assert_eq!(source, "hard-deny");
                // IP literal → denied_cidr, not denied_dns.
                assert!(reason == "denied_cidr" || reason == "denied_dns");
            }
            other => panic!("expected Deny(hard-deny), got {other:?}"),
        }
    }

    /// Test D: learned-allow skips deny_domain and allow_domain checks. [G-33]
    #[test]
    fn learned_allow_short_circuits() {
        let mut learned = LearnedStore::new();
        learned.insert_sync("api.example.com", LearnedEntry {
            allow: true,
            scope: "host".to_string(),
        });

        let host = "api.example.com";
        // NOT in allow_domain, NOT in deny_domain — only learned-allow matches.
        let allow: Vec<String> = vec![];
        let deny: Vec<String> = vec![];
        let resolved: Vec<IpAddr> = vec![];

        let outcome = pipeline_decision(host, &resolved, &allow, &deny, &learned);
        match outcome {
            PipelineOutcome::Allow { source, persisted, .. } => {
                assert_eq!(source, "learned");
                assert!(persisted);
            }
            other => panic!("expected Allow(learned), got {other:?}"),
        }
    }

    /// Test E: unclassified host (not in any list) → Unclassified.
    #[test]
    fn unclassified_host_returns_default() {
        let learned = LearnedStore::new();
        let host = "unknown.example.com";
        let allow = vec!["api.anthropic.com".to_string()];
        let deny: Vec<String> = vec![];
        let resolved: Vec<IpAddr> = vec![];

        let outcome = pipeline_decision(host, &resolved, &allow, &deny, &learned);
        assert!(matches!(outcome, PipelineOutcome::Unclassified));
    }
}
```

**Note on `LearnedStore` API:** the exact method names depend on D-3.3's implementation. `insert_sync` and `lookup_sync` are the synchronous variants (the store likely uses `parking_lot::RwLock` or `std::sync::RwLock` for the in-memory map, with async wrappers for the proxy path). If the store only has async methods, convert these tests to `#[tokio::test]` with `.await`.

### Step 4: Verify `handle_conn` uses `pipeline_decision`

After extracting `pipeline_decision`, `handle_conn` should call it for steps 1–4 and then handle the `Unclassified` case (step 5: prompt or `on_unavailable`). This is a refactor of the inline pipeline in D-3.6 — the logic is identical, just extracted into a testable function. The `handle_conn` code becomes:

```rust

}
```
